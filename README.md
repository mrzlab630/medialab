# Media Lab

Media Lab — локальный веб-интерфейс для генерации изображений и видео через совместимый с OpenAI API шлюз. Модели загружаются из шлюза; приложение не содержит собственных ключей или списка провайдеров.

## Запуск

Требуются Python 3, Node.js и PM2. Если PM2 ещё не установлен:

```bash
npm install --global pm2
```

Запустите приложение из каталога проекта:

```bash
pm2 start ecosystem.config.cjs --only medialab
```

Откройте <http://127.0.0.1:4173/>. По умолчанию сервер привязан к `0.0.0.0`, поэтому его можно открыть с другого компьютера в локальной сети по адресу хоста, например `http://192.168.0.194:4173/`. Для режима только на этом компьютере задайте `MEDIA_BIND_HOST=127.0.0.1` в окружении PM2. Конфиг [`ecosystem.config.cjs`](ecosystem.config.cjs) запускает один Python-процесс `medialab` в фоне и перезапускает его при сбое. Рабочий каталог определяется расположением конфига; порт можно изменить в `args`. Логи PM2 хранятся вне проекта, по умолчанию в `~/.pm2/logs/`.

Команды управления:

```bash
pm2 status medialab
pm2 logs medialab --lines 50
pm2 restart medialab
pm2 stop medialab
```

После изменения конфига примените его повторно:

```bash
pm2 startOrRestart ecosystem.config.cjs --only medialab --update-env
```

PM2 должен быть единственным процессом приложения на выбранном порту. Если сервер раньше запускался вручную, остановите его перед первым запуском PM2.

По умолчанию API-шлюз доступен на `http://127.0.0.1:8317`. Его адрес и необязательный API key задаются в настройках интерфейса. Переменная `MEDIA_GATEWAY_URL` меняет адрес шлюза для серверного проксирования готовых видео и запросов агентского API. Переменные сервера передавайте через окружение PM2; при их изменении используйте команду с `--update-env` выше. Не записывайте ключи в конфиг репозитория.

Для загрузки видео-референсов Seedance передайте ключ через переменную окружения `MEDIA_ASSET_API_KEY` либо задайте `APIAW_API_KEY` во внешнем env-файле шлюза. Поддерживаются переменные `MEDIA_ASSET_API_BASE` и `MEDIA_ASSET_ENV_FILE`; секреты не храните в репозитории.

## Возможности

- Генерация изображений через `POST /v1/images/generations`.
- Генерация видео через `POST /v1/videos/generations` с опросом статуса задачи.
- Выбор модели из `GET /v1/models`, быстрый поиск, промпт, формат и длительность.
- До 10 изображений или видео в качестве референсов; поддержка зависит от модели.
- Настройка генерации звука для поддерживаемых видео-моделей.
- Локальная библиотека результатов в `library/`, сохраняемая между запусками.
- Прямой HTTP API для ИИ-агентов: каталог моделей, фоновые генерации, статусы и скачивание результатов, без авторизации.

Верхняя панель содержит справку «ИИ агентам», настройки подключения ⚙ и обновление моделей ↻. Пока каталог загружается, иконка обновления вращается, повторный клик заблокирован. Счётчики ▧ и ▶ показывают количество моделей изображений и видео по тем же правилам, что списки выбора. Названия типов доступны при наведении. Боковой панели навигации и отдельного индикатора шлюза нет.

Для редактирования изображений GPT/Grok используется `POST /v1/images/edits` с multipart-полями `image[]`. Seedream получает JSON-поле `image` через `/v1/images/generations`. Для `dreamina-seedance-2-5-260628` референсы загружаются сервером в APIAW `/v1/assets`, затем их HTTPS-ссылки передаются в `images` или `videos`. Другие видеомодели получают `input_reference`; совместимость зависит от поставщика.

Переключатель «Генерировать звук» по умолчанию выключен. Для поддерживаемых моделей он передаёт `generate_audio: true/false`. Готовые видео скачиваются через серверный маршрут `/api/videos/{task_id}/content`; изображения и видео сохраняются через `/api/library`.

Карточка библиотеки открывает отдельное окно просмотра с промптом, моделью, датой, размером файла и сохранёнными настройками. Кнопка «Создать на основе этого» переносит настройки в форму, не запуская генерацию. Для новых работ сохраняются размер запроса, длительность, звук и количество референсов. У старых работ отсутствующие настройки помечаются; исходные файлы референсов нужно добавить заново.

В библиотеке по умолчанию отображается 10 карточек. В списке «Показывать» можно выбрать 10, 30, 50 или 100; кнопки «Назад» и «Далее» переключают страницы. Счётчик показывает диапазон и номер страницы. Изменение размера страницы и добавление новой работы возвращают на первую страницу; старые записи остаются доступны.

Seedance может отклонить реалистичный портрет, даже если персонаж сгенерирован ИИ. Уточняйте требования в [официальном руководстве по портретным материалам](https://docs.byteplus.com/en/docs/modelark/seedance-portrait-asset-guide). Наличие модели в каталоге не гарантирует доступность генерации у поставщика.

Библиотека и тестовые материалы в `artifacts/` предназначены для локального использования и исключены из Git. При клонировании они не загружаются.

## ИИ-агенты

Кнопка **«ИИ агентам»** в верхней части интерфейса открывает порядок работы, ссылки на OpenAPI, каталог моделей и полную документацию. Готовую инструкцию можно скопировать и передать агенту; адрес в ней соответствует открытому приложению, в том числе при доступе из LAN. Если браузер не разрешает копирование, текст выделяется для ручного копирования.

Точка входа: <http://127.0.0.1:4173/api/agent>. OpenAPI-схема: <http://127.0.0.1:4173/api/agent/openapi.json>. Агент создаёт задачу через `POST /api/agent/jobs`, опрашивает полученный `status_url` и скачивает `results[].url`. Изображения и видео сохраняются в общую библиотеку.

Выбран API в существующем сервере без новых зависимостей. MCP-сервер не требуется. Доступ открыт без токенов; сервер использует `MEDIA_GATEWAY_URL`, независимо от настроек браузера. Порядок подключения, примеры и правила повторных запросов — в [документации агентского API](docs/AGENT_API.md).

## Данные и безопасность

Правила исключения файлов находятся в [`.gitignore`](.gitignore). В Git не добавляются библиотека, сгенерированные и тестовые медиа, артефакты проверок, локальные env-файлы, ключи, логи, кэш Python и данные браузерной автоматизации. Настройки API key, введённые в интерфейсе, хранятся браузером в `localStorage` и не отправляются в репозиторий.

Проверьте индекс перед каждым коммитом:

```bash
git status --short
git diff --cached --name-only
```

Подробнее о границах локальных данных и секретах см. [документацию безопасности](docs/SECURITY.md).
