# Прямое взаимодействие с агентами

Выбран HTTP API с OpenAPI 3.1: он работает в существующем Python-сервере, не требует SDK, нового процесса или установки пакетов. Агенту достаточно HTTP-клиента или импорта OpenAPI в его инструменты. MCP удобен для автоматического обнаружения tools в совместимых клиентах, но потребовал бы отдельного адаптера и настройки каждого клиента. В этой версии используется HTTP API; MCP-сервера нет.

Базовый адрес: `http://127.0.0.1:4173`. Для агента на другом компьютере используйте LAN-адрес хоста. Авторизации, API key, OAuth и регистрации агентов нет. Все, кто имеет сетевой доступ к приложению, могут запускать генерацию и читать библиотеку.

В интерфейсе нажмите **«ИИ агентам»**: откроется краткое руководство со ссылками на схему, модели и эту документацию. Кнопка «Скопировать инструкцию» подготовит текст для агента с текущим адресом приложения. При запрете доступа к буферу обмена текст выделяется для ручного копирования.

Агент обращается к Media Lab, а сервер — к шлюзу из `MEDIA_GATEWAY_URL` (по умолчанию `http://127.0.0.1:8317`). Настройки адреса и ключа в браузере принадлежат браузеру и не влияют на агентский API. Сервер не передаёт Authorization в шлюз. Доступность `/v1/models` не гарантирует доступность генерации у провайдера.

## Контракт

| Запрос | Назначение |
| --- | --- |
| `GET /api/agent` | Обнаружение API и краткий порядок работы |
| `GET /api/agent/openapi.json` | Машиночитаемая схема для инструментов агента |
| `GET /api/agent/models` | Текущий каталог моделей шлюза |
| `POST /api/agent/jobs` | Запуск генерации; `202` и `status_url` |
| `GET /api/agent/jobs/{id}` | Статус, ошибка, `upstream_task_id`, результаты |
| `GET /api/agent/jobs` | Последние 50 задач |
| `GET /api/library` | Общая библиотека браузера и агентов |

Ссылки в ответах относительные: скачивайте `results[].url` с того же хоста Media Lab. Результаты сохраняются в `library/` и появляются в веб-библиотеке после обновления страницы. Агентский API не предоставляет удаления или отмены генераций.

Новые записи библиотеки и `results[]` содержат `parameters`: `size`, `reference_count`, а для видео также `seconds` и, при поддержке модели, `generate_audio`. Эти настройки доступны в окне просмотра библиотеки и переносятся в форму кнопкой «Создать на основе этого». У старых записей `parameters` может отсутствовать. Содержимое референсов не сохраняется.

Пример задания для агента:

> Используй Media Lab на http://127.0.0.1:4173. Прочитай /api/agent/openapi.json и /api/agent/models. Выбери подходящую модель, создай задачу через POST /api/agent/jobs с уникальным Idempotency-Key, опрашивай status_url раз в 4 секунды. При completed скачай results[].url. При failed или interrupted сообщи error.message; не запускай генерацию повторно автоматически.

## Изображение

Подставьте подходящий `model` из текущего каталога:

```bash
curl http://127.0.0.1:4173/api/agent/models

curl http://127.0.0.1:4173/api/agent/jobs \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: illustration-001' \
  -d '{"type":"image","model":"gpt-image-2.5","prompt":"Кот-космонавт на Луне","size":"1024x1024"}'

curl http://127.0.0.1:4173/api/agent/jobs/ID_ИЗ_ОТВЕТА
```

Обязательны `model` и `prompt`. По умолчанию `type=image`, `size=1024x1024`; создаётся один результат. Промпт — до 4000 символов, всё JSON-тело — до 100 MB. Список `references` принимает base64 data URL, HTTP(S)-ссылки и относительные URL существующих файлов библиотеки, например `/library/20261029-example.png`. Произвольные пути файловой системы не принимаются. Лимит — 10 референсов по 10 MB; Grok image 2.0 принимает до 5. Для изображения разрешены только изображения.

GPT/Grok и другие редакторы получают multipart `image[]` через `/v1/images/edits`. Seedream получает JSON `image` через `/v1/images/generations`; размеры из интерфейса преобразуются в увеличенные размеры Seedream. Фактическая поддержка параметров и референсов зависит от модели.

`size` передаётся шлюзу, но итоговый размер может отличаться: в реальной проверке `gpt-image-2.5` вернула PNG 1536×1024 при запросе 1024×1024. Проверяйте размеры скачанного файла, если они важны для задачи. Media Lab сохраняет результат без изменения размера.

## Видео

```json
{
  "type": "video",
  "model": "grok-imagine-video-1.5",
  "prompt": "Медленный пролёт камеры над морем",
  "size": "1280x720",
  "seconds": 6,
  "generate_audio": false,
  "references": []
}
```

Длительность по умолчанию — 5 секунд; API принимает целое число 1–60, ограничения выбранной модели проверяет шлюз. Видео создаётся через `/v1/videos/generations`. Сервер сам опрашивает удалённую задачу и скачивает файл. `generate_audio` поддерживают модели из описания OpenAPI; передача параметра неподдерживаемой модели возвращает `400`. По умолчанию звук выключен.

Seedance 2.5 использует тот же сервис загрузки референсов, что браузер. Для него нужны уже существующие настройки серверного сервиса assets, описанные в README; ключ доступа к самому Media Lab не нужен. Остальные видеомодели получают `input_reference`.

## Статусы и повторные запросы

`queued` → `running` → `completed` или `failed`. Ответ `202` означает принятие задачи, результат готов только при `completed`. Ошибка генерации находится в `error.message`.

Передавайте уникальный `Idempotency-Key` для каждого нового намерения генерации. Повтор с тем же ключом и телом вернёт прежнюю задачу с `200`, включая завершённую или ошибочную; другой запрос с тем же ключом вернёт `409`. Это работает после перезапуска. Без заголовка каждый POST создаёт новую генерацию. Провайдер может тарифицировать эти запросы.

Одновременно выполняются до двух агентских задач; третья получает `429`, её можно повторить позднее. Задачи браузера не входят в этот лимит. История хранится в `library/agent-jobs/`, без содержимого референсов. При перезапуске сервера незавершённые задачи становятся `interrupted` и автоматически не повторяются. Сбой сети также не отменяет задачу у поставщика: проверяйте `upstream_task_id`, прежде чем запускать её заново. Если поставщик долго держит статус ожидания, сервер продолжает опрос; отдельного метода отмены нет.

Ошибки API имеют форму `{"error":{"message":"..."}}`. Некорректные параметры возвращают `400`, неизвестные задачи — `404`, конфликт ключа — `409`, занятые слоты — `429`, недоступный каталог шлюза — `502`. Ошибки уже принятой генерации возвращаются в статусе задачи. Удаление файла через существующую очистку веб-библиотеки делает сохранённый URL недоступным и не меняет исторический статус задачи.

## Проверка

```bash
python3 -m unittest -v test_agent_api
```

Проверка запускает изолированные HTTP-серверы и временную библиотеку: изображения, редактирование, видео, Seedance assets, идемпотентность, конкурирующие записи, ошибки и восстановление после перезапуска. Реальные провайдеры и существующая библиотека не используются.
